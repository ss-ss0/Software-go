Lecture 1: Foundations of Software Engineering

المحاضرة الأولى

1. Software Engineering Definition (تعريف هندسة البرمجيات)

Software Engineering: An engineering discipline that is concerned with all aspects of software production from initial system specification through to maintaining the system after it has gone into use.
📌 الشرح بالعربي: هي تخصص هندسي يهتم بجميع مراحل إنتاج البرمجيات ابتداءً من تحديد الموصفات والأفكار الأولى للنظام، مروراً بالتصميم والتنفيذ والتحقق، وحتى الصيانة والتطوير بعد التشغيل الفعلي.

2. Product Specification (أنواع المنتجات البرمجية)

الخاصية (Feature) Generic Products Customized (Bespoke) Products
التعريف (Definition) Stand-alone systems developed for the open market. Systems commissioned by a specific customer for their needs.
مالك المواصفات (Specification Owner) Software Developer (الشركة المبرمجة) Customer (العميل)
أمثلة (Examples) MS Word, Photoshop, Operating Systems Air traffic control, University SIS, Hospital system

3. The 4 Essential Attributes of Good Software (الخصائص الأربعة للنظام الجيد)

1. Maintainability
Software should be written in such a way that it can evolve to meet changing customer needs.
💡 القابلية للصيانة والتعديل لمواكبة تغير متطلبات العميل مستقبلاً.
2. Dependability & Security
Includes reliability, security, and safety. Software should not cause damage in case of failure.
💡 الموثوقية والأمان: ألا يسبب النظام خسائر عند الفشل وأن يحمي البيانات.
3. Efficiency
Software should not waste system resources (memory, processor cycles, energy).
💡 الكفاءة: الاستغلال الأمثل للذاكرة والمعالج وعدم استهلاك الموارد.
4. Acceptability
Software must be acceptable to the type of users for which it is designed.
💡 القبول وسهولة الاستخدام: أن يكون السوفتوير مفهوماً ومقبولاً للمستخدمين.

4. Incremental Development (مهم جداً في امتحانات الميد)

نموذج التطوير التزايدي يقسم النظام إلى أجزاء (Increments) يتم تسليم كل جزء منها للعميل واختباره متتابعاً.
✅ 3 Benefits (الفوائد الرئيسية):
  • 1. Cost of accommodating changing customer requirements is reduced.
  • 2. Easier to get customer feedback on development work done.
  • 3. More rapid delivery and deployment of useful software to customer.
❌ 2 Problems (المشكلتان الأساسيتان):
  • 1. Process is not visible to managers (hard to measure progress).
  • 2. System architecture degrades as new increments are added.

Lecture 2 & Chapter 3: Requirements & Agile Development

المحاضرة الثانية والشابتر الثالث
Functional Requirements (المتطلبات الوظيفية)
Statements of services the system should provide, how it reacts to particular inputs, and behaves in specific situations.
💡 الوظائف والخدمات الفعالة التي يقدمها النظام للمستخدم (مثل: سحب المال في ATM أو البحث عن طعام).
Non-Functional Requirements (المتطلبات غير الوظيفية)
Constraints on services offered by system (timing, security, reliability, standards).
💡 القيود والجودة: مثل سرعة الاستجابة، نسبة الأمان، وتوفر الخدمة 24/7.

Pair Programming (Slide 28/29) - 4 Advantages

  • 1. Collective Ownership: الملكية الجماعية للكود بين المبرمجين وتجنب احتكار المعرفة.
  • 2. Real-time Code Review: مراجعة واكتشاف الأخطاء فوراً أثناء الكتابة مما يحسن الجودة.
  • 3. Encourages Refactoring: تشجيع إعادة هيكلة الكود لتحسين البنية دون خوف.
  • 4. Knowledge Sharing: تبادل الخبرات والمهارات بين الفريق بشكل مستمر.

Chapter 4: Software Architecture & 4+1 View Model

الشابتر الرابع

The 4+1 View Model (نموذج الرؤية المعمارية)

Logical View
Key abstractions, objects, and object classes.
💡 التجريدات والأوبجكت الكلاسات الأساسية.
Process View
Run-time interaction and thread concurrency.
💡 التفاعل وقت التشغيل والتزامن.
Development View
Code breakdown into modules and libraries.
💡 تقسيم الكود والموديلات والمكتبات.
Physical View
System hardware topology and network execution nodes.
💡 البنية التحتية الهاردوير والسيرفرات.
📌 +1 Scenarios (Use-Case View): يربط بين الرؤى الأربعة باستخدام حالات الاستخدام الواقعية للتأكد من اتساق المعمارية.

COCOMO Model (تقدير التكلفة والجهد)

KLOC = LOC / 1000
Effort (PM) = a * (KLOC)^b
Duration (TDEV) = c * (Effort)^d
مثال محلول (33,000 سطر كود Organic):
1. KLOC = 33,000 / 1000 = 33
2. Effort = 2.4 * (33)^1.05 ≈ 93.6 Person-Months
3. Duration = 2.5 * (93.6)^0.38 ≈ 14.1 Months
عدد المبرمجين = Effort / Duration ≈ 7 Developers

Software Myths vs. Facts

Myth: إضافة مبرمجين لمشروع متأخر يسرع التسليم (Brooks' Law).
Fact: إضافة أفراد جدد يزيد تأخير المشروع بسبب وقت التدريب والتواصل!
Myth: ينتهي العمل والمجهود بمجرد تسليم الكود.
Fact: 60% إلى 80% من إجمالي المجهود يحدث بعد تسليم النظام في مرحلة الصيانة.
